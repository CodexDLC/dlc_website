# DLC Montage: релизы

## До утверждения процесса

Конкретные ветки, форматы версий, среда выпуска и порядок миграций ещё не выбраны. Не вводить их самовольно.

## Базовые правила

- Каждое готовящееся к выпуску изменение классифицировать: исправление, функция, изменение данных или инфраструктурная работа.
- Изменения данных требуют обратимого плана миграции или явного решения владельца о несовместимости.
- В changelog фиксировать пользовательский эффект, а не внутренний дифф.
- Релиз должен ссылаться на прошедшие проверки и документированный способ отката, если он применим.
- Образы, Compose-слои и независимые restart-границы определяются навыком `dlc-deployment-architecture`; release flow не объединяет runtime-сервисы обратно в один образ.
